    Model Zoo¶

    This page lists OpenSportsLib checkpoints, config-only algorithms, and supporting model components published on Hugging Face. Task checkpoints can be loaded with load_weights(...); config-only algorithms and supporting components use the loading instructions in their sections below.

    Scores, class lists, and intended-use statements below come from model cards, published configs, or the library's component configuration. Scores are not computed or verified at documentation-build time. Missing training provenance and scores are marked Not reported. Follow each linked repository for its artifact details; a listing here does not certify end-to-end inference.

    Dataset/training source: SoccerNet - MVFouls classification subset, using video clips.

    skeleton-header-max-recall¶

    Hugging Face: OpenSportsLab/skeleton-header-max-recall

    This inference-only, rule-based algorithm detects headers from player-joint and ball HDF5 tracking inputs on CPU. The published config selects h5_header_skeleton_max_recall and the label header. It contains no learned checkpoint and does not support training. Reported scores: Not reported.

    The repository is gated. Request access on its Hugging Face page and, once approved, authenticate your local Hugging Face client before downloading. Use an OSL manifest referencing your own player-joint and ball HDF5 files; see the HDF5 header spotting guide for the input format.

    Download only the config and replace its machine-specific data paths:

    from huggingface_hub import hf_hub_download
from opensportslib.apis import Config, LocalizationModel

config_path = hf_hub_download(
    repo_id="OpenSportsLab/skeleton-header-max-recall",
    filename="config.yaml",
)
config = Config.from_file(config_path)
config.update(
    data={
        "data_root": "/path/to/tracking",
        "test_set": "/path/to/header_manifest.json",
    },
    runtime={"device": "cpu"},
)
model = LocalizationModel(config=config, weights=None)
predictions = model.infer(use_wandb=False)
model.save_predictions(output_path="header_predictions.json", predictions=predictions)

    Use Config.from_file for this downloaded config: Config.from_pretrained remembers the repository as a weight source, whereas this algorithm has no weights to load.

    Server loading: Register this repository as a localization model. The server recognizes its canonical MODEL.metadata.runner and loads it with weights=None. Gated access still requires an approved Hugging Face token. Existing deployments must include the config-only loading fix before using this registration path; see model registration.

    OSL-loc-tennis-public¶

    Hugging Face: OpenSportsLab/OSL-loc-tennis-public

    The repository contains config.yaml and model.pt for E2E tennis spotting. The published config specifies the rny002_gsm backbone, a GRU head, the labels no_swing and swing, and a DALI video loader. Its sampling uses an 11-frame clip at an extraction rate of 2 fps. The current config loader migrates the published legacy config when loading it.

    Training source: Not reported. Reported scores: Not reported. The repository has no model card; the architecture and labels above come from its config.

    Set local annotations and the root used to resolve their video paths before constructing the model. Config.from_pretrained downloads the config and remembers the repository ID; constructing LocalizationModel then loads the checkpoint.

    from opensportslib.apis import Config, LocalizationModel

config = Config.from_pretrained("OpenSportsLab/OSL-loc-tennis-public")
config.update(
    data={
        "data_root": "/path/to/tennis/videos",
        "test_set": "/path/to/tennis/test.json",
    },
    runtime={"device": "cpu"},
)
model = LocalizationModel(config=config)
predictions = model.infer(use_wandb=False)
model.save_predictions(output_path="tennis_predictions.json", predictions=predictions)

    The CPU example uses the library's OpenCV fallback. To use the published DALI route, install GPU support and DALI with opensportslib setup --dali, and select device="cuda". Provide an OSL JSON test manifest whose video paths resolve under your chosen data root.

    base_model_videoChatGPT¶

    Hugging Face: OpenSportsLab/base_model_videoChatGPT

    This is the decoder and tokenizer bundle used by the X-VARS VQA backend. The repository contains config.json, sharded safetensors weights, their index, and tokenizer files. Training source: Not reported. Reported scores: Not reported.

    The canonical opensportslib/configs/vqa/xvars.yaml already selects this repository. The relevant component setting is:

    MODEL:
  components:
    llm_decoder:
      params:
        repo_id: OpenSportsLab/base_model_videoChatGPT

    This is a fragment to apply to the X-VARS config, not a complete task config. The decoder works with the configured visual encoder, projector, and task adapter. See X-VARS setup and artifact flow for the workflow and OSL-VQA-XFOUL-XVARS-lora for the task adapter.

    trained-clip-vit-large-patch14¶

    Hugging Face: OpenSportsLab/trained-clip-vit-large-patch14

    This repository supplies model.pth.tar for the CLIP ViT-L/14 visual encoder used by the X-VARS configuration. Training source: Not reported. Reported scores: Not reported.

    The canonical opensportslib/configs/vqa/xvars.yaml selects the checkpoint and its corresponding architecture through these component settings:

    MODEL:
  components:
    video_encoder:
      load:
        weights_path: OpenSportsLab/trained-clip-vit-large-patch14
      params:
        vision_tower: openai/clip-vit-large-patch14

    Apply this fragment to the X-VARS config. Its visual-checkpoint resolver downloads model.pth.tar from the repository; vision_tower identifies the architecture and image processor used with those weights. The encoder supplies video features to the VQA pipeline. See X-VARS setup and artifact flow for feature extraction and index preparation.
